= Managing Secrets with the External Secrets Operator on OpenShift

Welcome to the Managing Secrets with the External Secrets Operator on OpenShift workshop!

== About this workshop

The External Secrets Operator (ESO) syncs secrets from an external secrets management system into native Kubernetes Secrets. It supports many providers. Red Hat tests the External Secrets Operator for Red Hat OpenShift with AWS Secrets Manager, HashiCorp Vault, Google Secret Manager, Azure Key Vault, and IBM Cloud Secrets Manager.

This workshop uses HashiCorp Vault as the example provider because it runs on your cluster and needs no cloud account. The `SecretStore` and `ExternalSecret` resources you create work the same way with every provider. Only the provider and authentication settings in the `SecretStore` change.

== What you'll learn

In this workshop, you will:

* Explain why Kubernetes Secrets stored in Git are a risk and how ESO addresses it
* Install the External Secrets Operator for Red Hat OpenShift
* Store secrets in the key/value (KV) engine of HashiCorp Vault
* Configure the Vault Kubernetes auth method so ESO authenticates with a service account instead of a static token
* Create a `SecretStore` that points at Vault
* Define an `ExternalSecret` that syncs Vault data into a native Kubernetes Secret
* Deploy a sample application that reads the synced Secret as environment variables and as a mounted volume
* Rotate a secret in Vault and observe how ESO refreshes it in the running application

== Who this is for

This workshop is designed for platform engineers, developers, and architects who want to sync secrets from an external secrets manager into Red Hat OpenShift Container Platform by using the External Secrets Operator.

**Experience level**: Beginner

== Prerequisites

Before starting this workshop, you should have:

* Basic familiarity with OpenShift and Kubernetes concepts (pods, namespaces, deployments, and Secrets)
* Command-line experience (Linux/Unix)
* Access to a web browser

No prior experience with HashiCorp Vault or the External Secrets Operator is required.

== Workshop environment

You will work in an OpenShift {ocp_version} cluster with cluster administrator access. All command-line work happens in the OpenShift Web Terminal, which already includes the `oc` and `helm` tools.

During the workshop, you will install HashiCorp Vault and the External Secrets Operator for Red Hat OpenShift yourself.

== Estimated time

This workshop will take approximately **1 to 1.5 hours** to complete.

* **Overview and environment setup**: Concepts and access to your cluster (10 minutes)
* **Module 1**: Install HashiCorp Vault and the External Secrets Operator (20 minutes)
* **Module 2**: Connect the External Secrets Operator to Vault (25 minutes)
* **Module 3**: Use synced secrets in a sample application (25 minutes)
